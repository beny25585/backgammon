# תוצאה רשמית בסיום טכני של סדרת טורניר

## התקלה שנמדדה — 31.10.2026

המשתמש דיווח על משחק שנתקע ב־1:1 אחרי פקיעת זמן. בדיקה לקריאה בלבד שהמשתמש הריץ בשרת זיהתה:

- טורניר 73, משחק 164, `TournamentLink` מספר 122, חדר `4121999f-ab38-41d0-a4a5-e0cb58a683a7`.
- החדר היה `completed`, בניקוד 1:1, עם יעד 5 ובקרת זמן `normal`.
- התוצאה הקפואה נשאה `winner_seat=p2`, סיבת `time` וניקוד `p1=1,p2=1`.
- המסירה הייתה `queued`, ומשימת המסירה הייתה `blocked` אחרי ניסיון אחד, עם `invalid_score`.

הקוד הסביר את הנתונים: פקיעת זמן סוגרת את כל הסדרה, אבל ניקוד המשחקון שנוסף יכול להשאיר תיקו. מקבל התוצאה בנוקאאוט דוחה תיקו ולכן אינו מקדם את העץ. גם תוצאה שאינה תיקו עלולה להיות סותרת: המנצח על זמן יכול עדיין להיות בפיגור בניקוד, והעץ בחר מנצח לפי הניקוד.

המשתמש בחר להמשיך במשחקון חדש מאותה תוצאת סדרה, עם זמן חדש לשני הצדדים. הוא הריץ שחזור מוגבל למשחק זה ודיווח על `RESTORED: fixture 164, score 1:1, new board, 5 minutes each.` השחזור שמר ארכיון של הסיום והמסירות הישנים, הפריד את רשומת הסיום הישנה מספירת תוצאות השחקנים ויצר גבול היסטוריה חדש. הפלט מעיד על סיום הטרנזקציה; כניסת שני השחקנים והמשך המשחק בפועל לא נצפו בידי העוזר.

## ההחלטה שאושרה

לאחר הצגת ההיקף המשתמש אישר ב„כן” לתקן את הדיווח ואת הקליטה. הניקוד המקורי ב־`GameRoom`, ב־`Match` ובמשחקונים נשמר. תוצאת הטורניר הרשמית נפרדת ממנו בסיום טכני: המנצח מקבל את יעד הסדרה, והמפסיד שומר את ניקודו.

לדוגמה, בסדרה עד 5, אם הניקוד שנשמר הוא 1:1 והמנצח הטכני הוא p2:

```json
{
  "score": {"p1": 1, "p2": 5},
  "winner_seat": "p2",
  "end_reason": "time",
  "technical_result": {
    "reason": "time",
    "played_score": {"p1": 1, "p2": 1}
  }
}
```

גם `match_details` והשחזור ממשיכים לשקף את ההיסטוריה המקורית. אין הוספת משחקונים או נקודות קובייה מומצאות להיסטוריה.

## היקף המימוש

- `backend/game/link/outbox.py`: בעת יצירת גוף תוצאה חדש בלבד, תוצאת סיום טכנית של טורניר חיובי מקבלת ניקוד רשמי ומטא־נתוני הכרעה. הסיבות הן `time`, `leave`, `disconnect`, `inactivity_timeout`.
- הכלל אינו משנה משחק כסף, משחק ישיר בעל מזהים שליליים, סיום רגיל, ויתור על משחקון בודד, ביטול או ניקוד שנמסר במפורש למנגנון הקיים. חוזי המשחק והחישוב הפיננסי נשמרים.
- לפני יצירת התוצאה נבדקים המנצח, יעד בטווח 1–32767 וניקוד תקין. ניקוד המפסיד חייב להיות נמוך מהיעד. כשל מפסיק את ההכרעה בתוך הטרנזקציה הקיימת.
- `backgammon-tournaments-backend/tournaments/gamelink/views.py`: לפני כתיבת תוצאת הטורניר נבדקת התאמת מנצח מפורש לניקוד. בהכרעה טכנית מאומתים גם הסיבה, הניקוד המקורי והיעד מול `GameLink` הנעול, שהגדיר את חוזה הכניסה.
- תוצאות ישנות ללא מנצח מפורש, או עם `null`, שומרות על מדיניות הקליטה הקיימת. בדיקת איסור תיקו בנוקאאוט נשארת פעילה.
- המטא־נתונים נשמרים ב־`GameLink.raw_result` ובאירוע `FixtureAudit` של התוצאה.

אין שינוי מודלים או מיגרציה. יצירת התוצאה ומשימת המסירה נשארת באותה טרנזקציה של סיום המשחק. גוף התוצאה קופא פעם אחת; ניסיון מסירה חוזר אינו מחשב אותו מחדש מנתוני חדר שהשתנו. קליטה חוזרת של משחק שהושלם משתמשת בענף ה־idempotency הקיים, בלי קידום, פרס או דירוג נוספים. אין כאן טרנזקציה גלובלית בין שני שרתי Django; המסירה המתמשכת והקליטה החוזרת נשענות על מנגנון ה־outbox הקיים.

תוצאות ישנות שכבר נקפאו ונחסמו אינן משוכתבות או מופעלות מחדש אוטומטית. הטיפול במשחק 164 היה שחזור נפרד ומאושר.

## אימות מקומי

- AST ו־`compile` של ארבעת קובצי Python שנוספו או שונו עברו באמצעות Python 3.12.10, ללא ייבוא היישום או הרצת בדיקות. נדרשה גישה לקובץ ה־Python המותקן מחוץ ל־sandbox.
- סקירת מקור עצמאית כללה את סימטריית החוזה, הסיבות הטכניות, כיוון המושבים, rollback, תוצאה קפואה, כפילות מסירה ותאימות לכסף ולהודעות ישנות. שני פגמים בקוד הבדיקות תוקנו במהלך הסקירה.
- נוספו 29 מתודות בדיקה: 15 בצד המשחק ו־14 בצד הטורניר, עם תרחישי משנה. הן מכסות את אירוע ה־1:1, מנצח שהיה בפיגור, מושבים הפוכים, שימור היסטוריה, עזיבה בין משחקונים, מסירה חוזרת, קידום לגמר, פרס ודירוג ללא כפילות, קלט פגום ו־rollback.
- **הבדיקות נכתבו ולא הורצו.** לא בוצעו build, בדיקה מקוונת או פריסה של התיקון. לא בוצעו פעולות Git.

## פקודות למשתמש

בסביבת הבדיקות המוגדרת של שרת המשחק, מתוך `Backgammon Game/backend`:

```bash
python manage.py test game.link.test_technical_results game.tests.gameplay.test_series_endings game.tests.integration.test_forfeit_policy game.link.tests.ResultBodyTests game.link.tests.EnqueueResultTests game.link.tests.DeliveryRetryTests
```

בסביבת הבדיקות המוגדרת של שרת הטורנירים, מתוך `backgammon-tournaments-backend/tournaments`:

```bash
python manage.py test gamelink.test_technical_results gamelink.tests gamelink.test_ratings
```

לעצור בכשל. פרסום התיקון מחייב את גרסאות שני השירותים באמצעות נוהל הפריסה הקיים, לאחר הבדיקות. אחרי הפריסה יש לאמת בסביבת משחק מבוקרת: סיום על זמן, קליטת ניקוד רשמי עקבי, עליית המנצח הנכון ועדכון העץ, תוך שמירת הניקוד המקורי בתיעוד המשחק. עד אז אין ראיה שהשרת החי כולל את התיקון.
