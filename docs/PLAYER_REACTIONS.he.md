## ההתנהגות שאושרה ומומשה

- כפתור ליד פרטי השחקן פותח בורר נגיש עם חמש הודעות מוכנות: בהצלחה, מהלך יפה, תודה, כל הכבוד ומשחק טוב.
- שישה אימוג׳ים: 👍 👏 😄 🤔 😅 🎲.
- בועה ליד השולח אצל שני השחקנים, עם תוקף של ארבע שניות וכניסה/יציאה עדינה של180ms. הפחתת תנועה משאירה דהייה בלבד. מקום הבועה קבוע כדי לא להזיז נתונים בעת הופעה והיעלמות.
- מרווח של שלוש שניות בין שליחות, גם בכמה כרטיסיות או תהליכי שרת.
- השתקת היריב מקומית לחדר ולמושב. ביטול השתקה אינו מציג מחדש תגובה שהתקבלה בזמן ההשתקה.
- הודעות מתורגמות לפי שפת כל מקבל. אין הקלדה חופשית או היסטוריית הודעות.

הבורר משתמש ב־dialog של הדפדפן עם Escape ומיקוד מקלדת. שטחי המגע לפחות44px; במסכים צרים ששת האימוג׳ים מתחלקים לשתי שורות. הבועות נשארות בעמודת השחקנים ואינן שכבה מעל הלוח או השעונים. לא נוספו תלויות; האנימציה משתמשת ב־Motion שכבר קיים במשחק, והעיצוב ב־Tailwind.

## חוזה והפרדה מהמשחק

`playerReactions.ts` מחזיק רשימה סגורה של מזהים. `usePlayerReactions` מנהל תפוגה, הגבלת שליחה מיידית, ניקוי וזיהוי אירועים כפולים. הרכיבים `PlayerReactionPicker` ו־`PlayerReactionBubble` מציגים את הבורר והבועה; `SidePanel` מרכיב אותם לצד השחקנים.

הלקוח שולח `player_reaction` עם `reactionId` בלבד. `reactions.py` בודק חברות עדכנית בחדר פעיל עם שני מושבים אנושיים, בוחר את צבע השולח וקובע מזהה ותפוגה. Redis אוכף את המרווח באמצעות פעולה אטומית משותפת לפי חדר ומשתמש. חוסר זמינות של Redis חוסם רק את התגובה.

האירוע משודר בסוג קבוצה נפרד, שאינו מותר ברשימת האירועים של הצופים. זמן התצוגה שנותר מחושב מחדש בכל חיבור לפני המסירה; אירוע שפג תוקפו נזרק. הלקוח משתמש במשך היחסי כדי לא להיות תלוי בהתאמת שעון המכשיר לשרת. אין שחזור תגובות לאחר חידוש חיבור.

שגיאות משתמשות ב־`player_reaction_error`, בנפרד משגיאות משחק. תגובות אינן נכנסות למנעול פעולות המשחק, אינן נרשמות כמהלכים ואינן משנות שעון, טיימר חוסר פעילות או תוצאה. חידוש חיבור, ניתוק, סיום משחק והחלפת חדר/מושב מנקים את התצוגה. מאזיני התגובות מתעדכנים בלי לפתוח חיבור מחדש כשהשרת מתקן צבע שחקן.

שרת המשחק מפרסם `supportsPlayerReactions` במצב הראשוני. החזית מציגה את הפקד במשחק אנושי בלבד ומאפשרת שליחה כשהמשחק זמין והיריב מחובר; AI, משחק מקומי וצופים אינם מקבלים אפשרות לשלוח. אין שינוי מסד או מיגרציה. נדרשים חזית ושרת מעודכנים כדי שהיכולת תופיע.

## אימות שבוצע

- TypeScript מלא של חזית המשחק עבר: `tsc --noEmit`.
- ESLint ממוקד בקבצי המקור והבדיקות הרלוונטיים עבר ללא שגיאות. ב־`GameBoard.tsx` נשארו שלוש אזהרות קיימות של `set-state-in-effect`; הקוד החדש אינו מוסיף אזהרות.
- בדיקת תחביר AST של ארבעת קובצי Python עברה, ללא ייבוא היישום או הרצת בדיקות.
- Ruff אינו מותקן בסביבת Python שנבדקה, ולכן לא הורץ lint של Python.
- סקירת מקור עצמאית בדקה הרשאות, קצב שליחה משותף, בידוד מצופים, תפוגה, החלפת חדר/מושב, השתקה והפרדה מפעולות המשחק.
- נוספו בדיקות שרת, hook ורכיבי תצוגה. הן **לא הורצו**.

לא הורצו tests או build, ולא בוצעו בדיקת דפדפן/מובייל או משחק חי. אין commit, push או פריסה.

```powershell

```

בדיקות השרת, בסביבת Python הפעילה של הפרויקט:

```powershell

python manage.py test game.tests.test_player_reactions
```
