# הרצה מקומית של 16 שחקנים

לתוספת של 32 שחקנים: [פקודה והסבר](LOCAL_32_PLAYERS.he.md).
`-Players` מקבל 16 או 32. בשני המצבים ברירת המחדל היא משחק רגיל ללא
עיכובי כניסה או רענון יזומים. מוסיפים `-RecoveryChecks` רק כשמבקשים
גם את תרחישי ההתאוששות האלה. זמני המוצר נשארים פעילים, והמשחק ממתין
לאירועים ואישורים אמיתיים במקום השהיה קבועה של 1.8 שניות.

לאימות כל תיקוני העומס וההתאוששות יחד, כולל tests, build ודוח משותף,
ראו [פקודת האימות המלאה](REPAIR_VALIDATION.he.md). העוזר לא הריץ אותם.

```powershell
Set-Location 'C:\Users\User\Desktop\projects\backgammon'
& '.\docs\tournament-e2e\run-tournament-e2e.ps1' -Headed
```

לצפייה בדפדפן מוסיפים `-Headed`; לצמצום עומס התצוגה עדיף להתחיל ללא הפרמטר.

התרחיש משתמש בקבצים המקומיים הנוכחיים, כולל שינויים שטרם פורסמו. הוא מפעיל
שני שרתי Daphne, שני עובדי משימות, Redis נפרד, שירות קוביות אמיתי וממשקי
Vue ו־React מ־production build דרך Nginx עם HTTPS. הסקריפט מזהה את
`tools\nginx-1.31.6\nginx.exe` שהוכן בפרויקט ואת Python שב־
`backgammon-tournaments-backend\venv`. אפשר להעביר במפורש
`-NginxExecutable`, `-GamePython` ו־`-TournamentPython` להתקנות אחרות.
אין צורך להפעיל את סקריפט הסביבה הרגיל.

ברירת המחדל היא PostgreSQL המקומי החדש בפורט 55432. הוא חייב להיות פעיל,
ושתי סביבות Python צריכות להכיל את דרייבר PostgreSQL שמוגדר ב־requirements
של כל שירות. ההרצה אינה מפעילה או מתקינה PostgreSQL/Nginx ואינה נופלת
ל־SQLite אם אחד מהם חסר. הגרסה הנוכחית הוכנה ולא הורצה בידי העוזר.

16 שחקנים מנסים להיכנס יחד. שמונה משחקים פועלים במקביל בסיבוב הראשון,
והתרחיש דורש 15 סיומים טבעיים עד הגמר, התקדמות ותשלום פרס אחד.
לאחר הסיום נשלחות התוצאות החתומות שוב כדי לבדוק שאינן מכפילות פרס.
אין מגבלת זמן לתרחיש או להמתנה להתקדמות; שעוני המשחק ומגבלות המערכת עצמה
נשארים פעילים. שגיאה מפורשת עדיין מכשילה את התרחיש.

הרתמה קוראת את סיסמת מנהל אשכול PostgreSQL המקומי רק כדי ליצור שני
מסדים ושני משתמשים חדשים בשם `e2e_<run_id>_game/tournament`. למשתמשי
הבדיקה אין הרשאות superuser או יצירת מסדים/משתמשים. רק המסדים החדשים
מקבלים מיגרציות ונתוני בדיקה; מסד העבודה אינו נקרא או מתאפס. המסדים
נשארים אחרי ההרצה לצורך אבחון, ואינם נמחקים אוטומטית. המפתחות חדשים,
קובצי `.env` הרגילים אינם נטענים. הפורטים 18805, 18806, 18573, 18574, 18679 ו־18807 חייבים
להיות פנויים. הבדיקה אינה שולחת פוש אמיתי ואינה משתמשת בתורי הפרודקשן.

בסיום שולחים רק את ZIP הדוח שמופיע אחרי `SEND THIS FILE:`; לא שולחים
את כל תיקיית ההרצה. במהלך הפעילות מופיעה הודעה כל 30 שניות שהתהליך חי,
שאינה כשלעצמה הוכחה להתקדמות המשחקים. Ctrl+C עוצר את הריצה.

לפני תרחיש 16 המשתתפים רצות בדיקות הנעילה החדשות של שני השרתים על
מסדי ההרצה. בדיקה שנכשלת או מדולגת עוצרת את ההרצה. הסטטוס נקרא
בטרנזקציה לקריאה בלבד, כולל גרסת PostgreSQL, בידוד ועמידות כתיבה.

נכללות גם בדיקות צמצום הקריאות במסלול המהלך: טעינת חדר ומצב יחד,
קריאה חדשה בכל הודעה, חסימת משחק שממתין להחלטת מארגן ואפשרות לעזוב,
וטיפול בבוט ובחדרים ישנים ללא מצב שמור. השינוי מצמצם את הכניסות לתור
המסד לפני ביצוע מהלך מארבע לאחת במצב הרגיל. ההשהיות של הממשק נשארות
כפי שהן. מדידת השיפור בפועל דורשת הרצה חדשה; הרצה שכבר פעילה ממשיכה
להשתמש בקוד שטענה בתחילתה. את ההרצה מבצע המשתמש.

`environment-summary.json` מכיל גרסאות Python/Node/Django/דרייברים,
טביעות קוד וממשקים, גרסת PostgreSQL והגדרות העובדים ברתמה.
נרשמות גם גרסת Redis ותצורת Mix/OTP; שירות הקוביות הקיים רץ ב־`MIX_ENV=dev`,
כי בפרויקט אין `config/prod.exs`. אין להסיק מכך שהשרת משתמש באותו מצב.
כדי להשוות
לתצורה **אחרי המעבר ל־PostgreSQL**, צריך דוח מאותה רתמה שהופקה בסביבת
Linux מבודדת עם הקוד והגרסאות המתוכננים לשרת. מוסיפים
`-ServerReference 'C:\reports\environment-summary.json'`. הבדלים בשדות
המושווים עוצרים את התרחיש ומופיעים בדוח; בלי קובץ ייחוס מצב ההשוואה
הוא `not_verified`. מלאי השרת הישן `server-preflight.json` אינו קובץ ייחוס
כזה, ואינו מוכיח את תצורת השרת העתידית.

Nginx ב־Windows מספק ניתוב דומה אבל בעל מגבלות ביצועים לפי
[התיעוד הרשמי](https://nginx.org/en/docs/windows.html). חומרה, Linux,
Redis/Elixir, ניתוב Nginx המדויק, מספר עובדי השרת והרשת עדיין דורשים
השוואה. אין לטעון להתאמה מלאה או לקיבולת שרת מתוך תוצאה מקומית.

לבדיקה מהירה של הפרופיל הישן בלבד משתמשים ב־`-Database sqlite -UiMode dev`;
הדוח יציין שאין כיסוי PostgreSQL. זה אינו פרופיל האימות המבוקש למסד החדש.
