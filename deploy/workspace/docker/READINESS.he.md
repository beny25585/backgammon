# מצב ההכנה לפריסה — 2026-10-05

התשתית נשמרת תחת `deploy/workspace` במאגר המשחק. הקוד נמשך מארבעת המאגרים
לתיקיית פריסה חדשה לפי ה־commits ב־`release.json`; התמונות נבנות בשרת.
סודות ונתוני ייצור אינם ב־Git. אין כאן אישור שהמערכת כבר נבדקה בפרודקשן.

## מה הוכן ונבדק מקומית

- Compose נפרד לפרודקשן, עם תמונות בגרסה מפורשת, משתמשים ללא root ביישומים,
  הגבלות זיכרון, health checks ופורט ציבורי רק דרך Nginx הקיים.
- שלושה מסדי PostgreSQL נפרדים: המשחק והטורנירים מועברים עם הנתונים שלהם;
  מסד הניתוח חדש וריק באישור המשתמש.
- לכידה פרטית של הסודות האפקטיביים, גיבוי, והעברת הטורנירים עם אימות מזהים,
  קשרים, ספירות וערכים כספיים. תרגול מבודד עם נתונים מלאכותיים עבר,
  לפי [TRANSFER-REHEARSAL.he.md](TRANSFER-REHEARSAL.he.md).
  טרם בוצע תרגול עם עותק מנתוני השרת.
- העובד של משימות הטורנירים נשאר בפרופיל נפרד שאינו מופעל אוטומטית.
- stdout/stderr לשרתי היישום ולעובדים, ותוספת Alloy עם אותם jobs של שרתי
  היישום. מקורות האיסוף והדשבורדים הקיימים אינם מוחלפים.
- Prometheus נפרד בפרופיל `monitoring`, תוספת Alloy למדדי שרת/קונטיינרים
  ודשבורד חדש עם שמונה פאנלים. נבדקו התחביר, JSON ושאילתות PromQL;
  קליטת מדדים אמיתית בשרת טרם נבדקה.
- אימות תחביר Compose לכל הפרופילים וגם לסביבה המקומית עבר.
- אימות תחביר תוספת Alloy עם receiver מקומי מדומה ב־Alloy 1.17.0 עבר,
  בקונטיינר מבודד ללא רשת וללא Docker socket. זהו lint, לא בדיקת קליטה.
- Ruff עבר על כלי הפריסה והתרגול ושלוש הגדרות Django בדוקר.
  תרגול הנתונים השתמש בתמונות מקומיות קיימות.
- קוד היישומים פורסם בארבעת המאגרים. המשתמש אישר שמשחק מקומי בין שני
  שחקנים הסתיים ושתוצאתו נשמרה בטורניר. אין בכך אימות פרודקשן או בדיקת עומס.
- בדיקת API לקריאה בלבד בשרת החזירה Grafana health תקין ורשומות Loki
  חדשות של job המשחק. זו הוכחה לאיסוף הקיים; תוספת Docker טרם הופעלה.

## פקודות המשתמש — build ובדיקות

הכן תיקיית פריסה לפי [מדריך Git](../README.he.md). הסקריפט יוצר
`docker/production.env` עם תג הגרסה שב־manifest. מתוך תיקיית הפריסה בשרת:

```bash
bash docker/build_on_server.sh
```

פקודות בדיקות האתרים לפי ה־scripts הקיימים, כל אחת בתיקיית האתר המתאימה:

```powershell
# Backgammon Game/frontend
pnpm test

# backgammon-tournaments
pnpm test:unit --run

# backgammon-tournaments-backend/admin-frontend
pnpm test:unit --run
```

את בדיקות Django הרץ בסביבת בדיקות מבודדת עם ההגדרות המתאימות לכל שירות.
אין להריץ `manage.py test` מול מסדי הייצור או להעניק CREATEDB למשתמשי
הפרודקשן כדי לעקוף הרשאות. בנייה מוצלחת אינה תחליף לתרגול הנתונים.

## אימות תהליכים וניקוי לאחר ההחלפה

בשרת, לאחר הגדרת `dc` לפי מדריך הפריסה:

```bash
dc --profile live --profile workers ps -a
dc --profile live --profile workers logs --since 10m --tail 100
systemctl --failed --no-pager
systemctl list-timers --all --full --no-pager
sudo -u administrator crontab -l
sudo cat /etc/cron.d/backgammon-tournaments-tasks
docker stats --no-stream
```

בדוק שכל API והתשתיות healthy, העובדים הנחוצים running ללא לולאת restart,
ושה־health והלוגים חדשים. ל־workers אין health check עסקי אוטומטי: יש
לאמת פעילות אמיתית ותורים. שירותי migration חד־פעמיים שסיימו ב־exit 0
יכולים להופיע exited; זה אינו כשל. גם oneshot ישן במצב inactive אינו כשל.

בתהליך ההחלפה מפסיקים ומבטלים הפעלה אוטומטית רק של היחידות שהוחלפו:
`backgammon.service`, `backgammon_tournaments_backend.service`,
`backgammon-analysis.service`, `backgammon-analysis-worker.service`,
`backgammon-push.service`, `dice.service`, ושני שירותי/טיימרי המשימות של
Backgammon. מסירים רק את תזמוני Backgammon המתאימים מה־cron, כולל הכפילות
של משימות המשחק; מגבים את ההגדרות לפני שינוי. התזמון של shesh_besh_bot
ויתר היישומים נשארים. אין צורך לעצור PostgreSQL/Redis של המחשב, Nginx,
Certbot, Grafana, Loki או Alloy.

`t32-task-probe-1.service` הוא probe שנכשל בעבר. סקור אותו לפני ניקוי מצב
failed; אין להסיק מהדגל בלבד שיש תהליך פעיל שצריך להרוג. השהיית משימות
הטורנירים נשמרת. לא מפעילים את הפרופיל שלהן כדי להשיג רשימת שירותים ירוקה.

מדדי CPU וזיכרון והוספת מקור הנתונים החדש מפורטים ב־[METRICS.he.md](METRICS.he.md).
