# תרגול העברת נתונים — 2026-10-05

תרגול מלא עבר מקומית עם נתונים מלאכותיים בלבד. הוא השתמש בתמונות Docker
קיימות ובקוד המקור הנוכחי, בפרויקט זמני נפרד עם PostgreSQL 16, רשת פנימית
ללא פורטים, סודות חדשים ומסדי נתונים חדשים. APIs ועובדים לא הופעלו.
מסדי Docker המקומיים שבהם המשתמש בודק לא שונו. אין כאן תרגול על נתוני Bot1.

## מה עבר

| מסלול | אימות |
| --- | --- |
| טורנירים: SQLite → snapshot → JSON → PostgreSQL | כל מודל: ספירה, מזהים, hash של שדות/קשרים וסכומי Decimal |
| ירושת מודלים בטורניר | רשומת Mode אחת ורשומת Knockout אחת, עם הקשר המקורי ביניהן |
| ארנקים | שתי עסקאות; סכום amount וגם balance_after הוא 1,875.75 בכל צד |
| משתמשים והרשאות | שני משתמשים עם מזהים 11 ו־27, קבוצה והרשאות many-to-many |
| רשומות משחקי טורניר | Fixture ושני קשרי confirmation; לא נבדק משחק בדפדפן |
| תורים | משימת תפוגה ראשונית ומשימה מלאכותית עם JSON נשמרו |
| ייבוא חוזר למסד מאוכלס | נחסם בגלל נתונים קיימים; אימות נוסף הוכיח שהנתונים נשמרו |
| משחק: PostgreSQL → pg_dump → pg_restore למסד ריק | fingerprint זהה לכל המודלים לפני ואחרי השחזור |
| נתוני המשחק | שני שחקנים, חדר אחד, שני מושבים, מצב JSON ותוצאת Match |
| רצפי משתמשים | יצירת משתמש קיבלה מזהה מעל 27 בשני יעדי השחזור; הרשומה עצמה בוטלה |

התהליך אינו בונה תמונות ואינו מפעיל tests של היישומים. הוא מפעיל מיגרציות
ופעולות גיבוי/ייבוא רק במסדים המלאכותיים. בסיום הוא מסיר את הקונטיינרים,
הרשת וה־volumes המלאכותיים של הפרויקט שהוא יצר בלבד.

## תיקונים שהתגלו בתרגול

1. מסד טורנירים חדש מכיל קטלוג שנוצר במיגרציה. הכלי מאפשר רק את ארבע
   הרשומות הראשוניות כאשר ערכיהן לא השתנו; עסקאות, משתמשים, sessions,
   קטלוג ששונה או משימות שאינן ראשוניות עדיין חוסמים ייבוא.
2. JSON של המשימה הראשונית נבדק באמצעות ORM, כדי להימנע מהבדלי ייצוג
   בין מנהלי ההתקן של PostgreSQL.
3. מנהל polymorphic החזיר את רשומת הבן גם כשנשאלה טבלת האב. הייצוא
   מבטל downcasting בזמן הסריאליזציה ושומר כל מודל בנפרד. נוסף גם אימות
   שמספר הרשומות המיוצאות תואם למקור. המקור והיעד נבדקים באותה דרך.

הגישה למודלים בירושה תואמת את
[תיעוד django-polymorphic](https://django-polymorphic.readthedocs.io/en/stable/advanced.html#working-with-fixtures)
ואת [תיעוד הסריאליזציה של Django](https://docs.djangoproject.com/en/4.2/topics/serialization/#inherited-models).
מזהי ContentType נכללים בייצוא ושומרים על ערכי המקור; אין שימוש ב־natural
primary keys שמחליפים מזהי משתמשים או קשרים.

## הרצה חוזרת במחשב המקומי

מתיקיית הפרויקט, כאשר Docker והתמונות המקומיות קיימים:

```powershell
python .\docker\rehearse_transfer.py
```

אפשר לבחור תמונות פרודקשן שכבר נבנו, באמצעות `--game-image` ו־
`--tournaments-image`. הכלי מקבע את מזהי התמונות בתחילת ההרצה ואינו משנה
אותן. כל הרצה יוצרת תיקיית `docker/.production/rehearsal-*` חדשה; הדוח
`report.json` מציג `status: passed` ו־19 שלבים, כולל ניקוי. הלוגים,
ה־snapshot והגיבויים נשארים בתיקייה המקומית ולא נכללים בחבילת הפריסה.
עותק הדוח האחרון עם מזהי התמונות ו־hash של כלי התרגול נמצא ב־
[transfer-rehearsal-20261005.json](transfer-rehearsal-20261005.json).
קוד יציאה 1 בשלב הייבוא החוזר הוא הסירוב הצפוי שנבדק, ולא כשל בתרגול.

עדיין נדרש לפני ההחלפה תרגול על עותק נתוני השרת, עם גרסאות קוד ומיגרציות
שתואמות למקור וליעד. לא נבדקו כאן עומס, התחברות בדפדפן, חיובים, WebSocket,
callbacks, Push או ניתוח. אלה נבדקים בנפרד לפי
[READINESS.he.md](READINESS.he.md) ו־[PRODUCTION.he.md](PRODUCTION.he.md).
